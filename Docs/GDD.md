# Pick & Shoot — Game Design Document

> 가제. 본 문서는 MVP 검증 단계의 기획서이며, 실제 구현 및 플레이 테스트 결과에 따라 갱신된다.

---

## 1. 게임 개요

| 항목 | 내용 |
|------|------|
| 장르 | 로그라이크 액션 슈팅 |
| 플랫폼 | PC 우선 |
| 관점 | (미정 — Top-down 2D 유력) |
| 조작 | 키보드 + 마우스 |
| 세션 길이 | 1회 러닝 20~40분 (목표) |
| 핵심 키워드 | 탄환 회수 / 자원 관리 / 전투 / 로그라이크 |

### 한 줄 피치

> **내가 쏜 총알을 다시 주워야 살아남는 로그라이크 슈팅 게임.**

### 핵심 디자인 원칙

**탄환은 소비되는 자원이 아니라, 전장에 배치되는 자원이다.**

일반적인 슈팅 게임처럼 탄환을 소비하고 재장전하는 것이 아니라, 발사한 탄환을 전장에서 직접 회수하여 다시 장전한다.

```
Pick → Shoot → Pick → Shoot
```

### 모티브 / 레퍼런스

| 레퍼런스 | 가져오는 요소 |
|---------|-------------|
| **Brotato** | 로그라이크 슈팅의 세션 구조 · 웨이브 기반 진행 · 업그레이드 선택 |
| **Vampire Survivors** (뱀서라이크) | 뱀서라이크 계열의 밀도 있는 적 처리감 · 짧은 세션 · 성장 곡선 감각 |
| **Pinball** | 탄환 튕기기 — 벽/오브젝트에 튕겨 재활용되는 물리적 재미 |
| **PengPong** (Steam) | 회수 시스템 — 발사체를 다시 주워 쓴다는 감각의 참고 |

각 레퍼런스는 "그대로 차용"이 아닌 **핵심 감각의 참고**. Pick & Shoot 고유의 차별점은 **회수가 전투 루프의 필수 요소**라는 점이다. (Brotato/뱀서의 자동 사격, PengPong의 캐주얼 회수와 달리, 이 게임에서 회수는 생존을 위한 능동적 선택이다.)

## 2. 핵심 플레이 루프

1. 탄환을 장전한다.
2. 적을 향해 사격한다.
3. 탄환이 적, 벽, 바닥 등에 박힌다.
4. 탄환을 회수한다.
5. 회수한 탄환을 다시 장전한다.
6. 적을 처치하고 다음 전투로 이동한다.
7. 전투 후 업그레이드를 선택한다.
8. 더 강한 적과 전투한다.

### 플레이어가 매 순간 마주하는 선택

- 이 탄환을 **어디에** 쏠 것인가? (회수하기 쉬운 위치인가?)
- 지금 회수하러 가도 **안전한가**?
- 적을 **빠르게 처치**할 것인가, 회수하기 좋은 위치에서 **끌면서** 싸울 것인가?
- 어떤 **업그레이드**로 회수/사격을 강화할 것인가?

## 3. 주요 시스템

### 3.1 탄환 — 공통 원칙

모든 탄환이 공통으로 따르는 규칙. 개별 탄환의 스탯(발사 속도·튕김 횟수·피해·넉백 등)은 **발사한 무기가 정의**한다 ([Docs/Systems/Weapons.md](Systems/Weapons.md) 참조).

탄환은 **발사 후 사라지지 않고** 월드에 남으며, 발사 순간부터 **튕김 → 정착** 두 페이즈를 순차 진행한다.

**튕김 페이즈** (발사 직후)

- **속도와 충돌판정을 그대로 유지**한 채 정해진 카운트(`튕김 횟수`)만큼 튕긴다 (감속 없음).
- **튕김 대상은 3종**: 적, 벽, 화면(카메라) 가장자리. 튕김이 실제로 발생할 때마다 카운트를 1 소비한다.
  - **벽** — 핀볼식 반사. 반사 각도는 법선 기준 콘(cone) 안으로 클램프하여 얕은 각도 튕김을 방지, 최소 속도 보장.
  - **화면 가장자리** — 카메라 뷰포트 밖으로 벗어나면 안쪽으로 반사. 규칙은 벽과 동일. 카메라 안에서 항상 액션이 유지된다.
  - **적** — 데미지·넉백을 준 뒤 **관통 규칙**에 따라 처리 (아래).
- 카운트 소진 즉시 정착 페이즈 전환.

**적 적중 — 관통 카운트**

무기 스탯 **`관통 N`**은 "적을 N번 그대로 통과한다"는 뜻이다. 튕김과 별개의 독립 카운트.

- **관통 카운트 > 0** → 적 적중 시 통과. 관통 카운트 1 소비, 튕김 카운트 미소비. 속도·방향 유지.
- **관통 카운트 = 0** → 적 적중 시 벽과 동일하게 튕김. 튕김 카운트 1 소비.
- 관통·튕김 여부와 무관하게 데미지·넉백은 매 적중 정상 적용.
- 벽·화면 튕김은 관통 카운트에 영향을 주지 않는다.
- 예시: `튕김 횟수=3, 관통=2`인 라이플 탄환은 벽 튕김을 아끼면 2 관통 + 3 적 튕김 = **5명의 적 명중** 가능.

**정착 페이즈**

- **감속** 시작 → 서서히 정지.
- **적과 물리 충돌 없음** — 공중을 그대로 통과. 데미지·넉백 없음.
- **벽·화면 가장자리 튕김도 종료** — 감속 중 자연스럽게 멈춘다.
- **회수 가능** — 플레이어 자석 반경 진입 시 → 발사한 무기의 탄창에 1발 충전 ([3.2 탄환 회수](#32-탄환-회수)).

**공통**

- 탄환끼리 서로 겹치지 않도록 분리 힘 적용 (양 페이즈 모두).
- 탄환은 **월드 오브젝트**이며 시야에 명확히 보여야 한다. (가시성이 재미의 핵심)

> 감속률·최소 튕김 속도·반사 콘 각도 등 세부 수치는 **튜닝 대상**.

### 3.1.1 스테이지 구조

- **영역 제한 필드** (Brotato 방식) — 뱀서처럼 무한 스크롤하지 않는다.
- 플레이어는 정해진 사각/원형 아레나 안에서 전투.
- 맵 **가장자리 = 튕김 벽**. 탄환은 필드 밖으로 나가지 않고 벽에 튕겨 다시 필드로 돌아온다.
- **카메라는 플레이어를 따라간다** — 아레나 전체를 한 화면에 담지 않는다. 단, 시야는 울타리 바깥 한 칸까지만 닿는다 (아레나 밖이 화면을 차지하지 않게). 시야가 아레나보다 넓은 축은 아레나 중앙에 고정된다. 화면 가장자리 튕김([3.1](#31-탄환--공통-원칙))의 기준선도 카메라와 함께 움직인다.
- 이 구조가 만드는 것:
  - **모든 탄환은 반드시 회수 가능한 위치에 남는다** (필드 밖으로 유실되지 않음)
  - 벽을 이용한 **의도적 튕김 사격** 전략 성립
  - 뱀서라이크의 밀도감을 **좁고 명확한 공간**에서 재현

### 3.2 탄환 회수

- 회수한 탄환은 다시 장전할 수 있다.
- **MVP 회수 방식**: 탄환에 접근 → 자동 회수
- (확장) 회수 범위 증가, 자동 회수 확률, 회수 속도 등을 업그레이드로 추가

### 3.3 전투

- 적은 플레이어를 추적하거나 공격한다. 적 타입·행동 규칙은 [Docs/Systems/Enemies.md](Systems/Enemies.md) 참조.
- **피격 표시** — 입은 데미지를 피격 대상 위에 숫자로 띄운다. 적 피격은 흰색, 플레이어 피격은 붉은색으로 구분한다.
- **웨이브 클리어 시 체력 전체 회복** — 웨이브 종료 후 클리어 대기(탄환 sweep)가 끝나는 시점에 체력을 완충한다. 업그레이드 선택과 다음 웨이브 카운트다운은 이미 가득 찬 체력으로 맞이하며, 이전 웨이브의 피해가 다음 웨이브로 누적되지 않는다.
- 플레이어는 **제한된 탄환**을 효율적으로 사용하면서 적을 처치한다.
- 동시에 발사된 탄환을 **회수해야** 지속 전투가 가능하다.
- **탄환이 0이 되면?** — 회수하러 가거나, 회피에 집중해야 한다. (탄환 부족 = 긴장감)

### 3.4 로그라이크 성장

전투/스테이지 클리어 후 무작위 업그레이드를 선택한다. 성장은 **두 축**으로 구성되며, 조합이 빌드 다양성을 만든다.

- **무기 축 (개별)** — 새 무기 획득 또는 보유 무기 강화. 상세는 [Docs/Systems/Weapons.md](Systems/Weapons.md).
- **공통 축** — 무기와 무관하게 캐릭터·탄환·회수에 두루 적용되는 능력.

**업그레이드 예시**

| 카테고리 | 예시 |
|---------|------|
| 무기 | 새 무기 획득 (슬롯 확장 포함), 공격력 증가, 발사 속도 증가, 최대 탄약 증가 |
| 공통 | 이동 속도, 최대 체력, 회수 범위, 회수 속도, 탄환 잔류 시간, 튕김 감쇠 감소, 튕김 시 피해 증가, 회수 시 체력 회복, 확률적 자동 회수, 회수 시 이동속도 증가 |

> 무기 축은 **어떻게 싸울지**를, 공통 축은 **캐릭터와 탄환 시스템의 기반**을 강화한다.

**확장 방향 (Phase 매핑)**

- **Phase 3** — 무기 축만 도입. 로그라이크 흐름(웨이브 반복·업그레이드 선택 UI)과 무기 획득/강화를 함께 검증.
- **Phase 4+** — 공통 축 확장, 폭발형 무기 등 추가. "무기 조합 + 무기 강화 + 공통 업그레이드"의 복수 축 빌드 시스템으로 완성.

## 4. MVP

### 목표

> **"탄환을 쏘고, 주워서 다시 쏘는 것이 실제로 재미있는가?"**

를 검증하는 것이 MVP의 최우선 목표다.

### 필수 구현

**플레이어**
- 이동 / 조준 / 사격
- 탄환 장전 / 탄환 회수

**탄환**
- 발사 / 충돌 / 월드에 잔류 / 회수 가능 / 재장전 가능

**적**
- 기본 적 1종
- 플레이어 추적 / 피격 / 사망

**전투**
- 제한된 탄환
- 적 처치 → 탄환 회수 → 반복 전투

**스테이지**
- 영역 제한 아레나 1개 (사각형)
- 가장자리 벽 = 탄환 튕김 벽
- 적 웨이브
- 웨이브 클리어 조건

### MVP에서 제외

- 다양한 무기 ([Docs/Systems/Weapons.md](Systems/Weapons.md) 참조) / 다양한 탄환 종류
- 복잡한 로그라이크 메타 성장
- 상점 / 보스 / 스토리
- 복잡한 맵 생성
- 온라인 기능
- 고품질 아트

## 5. MVP 테스트 기준

다음 질문에 **YES**가 나오면 다음 개발 단계로 넘어간다.

| # | 검증 질문 |
|---|----------|
| ① | 탄환이 바닥에 떨어져 있는 것이 실제 게임 플레이에 의미가 있는가? |
| ② | **탄환을 회수하기 위해 이동하는 것이 귀찮음보다 재미가 큰가?** |
| ③ | 탄환을 어디에 쏠지 고민하게 되는가? |
| ④ | 탄환이 부족할 때 긴장감이 발생하는가? |
| ⑤ | 적을 공격하는 것과 탄환을 회수하는 것 사이에 의미 있는 선택이 발생하는가? |

**특히 ②가 중요하다.** 탄환 회수가 단순한 청소 작업처럼 느껴진다면 시스템을 수정해야 한다.

### ②에 대한 수정 방향(참고)

- 회수 자체에 **보상감** 부여 (사운드/이펙트/즉시 재장전)
- 회수 이동 중에도 **의미 있는 위험**이 존재하도록 적 배치
- 회수를 **전략적 선택**으로 만드는 업그레이드 조기 도입
- 자동 회수 요소로 청소감을 줄이되, **자동화가 재미를 빼앗지 않도록** 균형 조절
