# Pick & Shoot — Game Design Document

> 가제. 본 문서는 MVP 검증 단계의 기획서이며, 실제 구현 및 플레이 테스트 결과에 따라 갱신된다.

---

## 1. 게임 개요

| 항목 | 내용 |
|------|------|
| 장르 | 로그라이크 액션 슈팅 |
| 플랫폼 | PC 우선 |
| 관점 | (미정 — Top-down 2D 유력) |
| 조작 | 키보드 + 마우스 |
| 세션 길이 | 1회 러닝 20~40분 (목표) |
| 핵심 키워드 | 탄환 회수 / 자원 관리 / 전투 / 로그라이크 |

### 한 줄 피치

> **내가 쏜 총알을 다시 주워야 살아남는 로그라이크 슈팅 게임.**

### 핵심 디자인 원칙

**탄환은 소비되는 자원이 아니라, 전장에 배치되는 자원이다.**

일반적인 슈팅 게임처럼 탄환을 소비하고 재장전하는 것이 아니라, 발사한 탄환을 전장에서 직접 회수하여 다시 장전한다.

```
Pick → Shoot → Pick → Shoot
```

### 모티브 / 레퍼런스

| 레퍼런스 | 가져오는 요소 |
|---------|-------------|
| **Brotato** | 로그라이크 슈팅의 세션 구조 · 웨이브 기반 진행 · 업그레이드 선택 |
| **Vampire Survivors** (뱀서라이크) | 뱀서라이크 계열의 밀도 있는 적 처리감 · 짧은 세션 · 성장 곡선 감각 |
| **Pinball** | 탄환 튕기기 — 벽/오브젝트에 튕겨 재활용되는 물리적 재미 |
| **PengPong** (Steam) | 회수 시스템 — 발사체를 다시 주워 쓴다는 감각의 참고 |

각 레퍼런스는 "그대로 차용"이 아닌 **핵심 감각의 참고**. Pick & Shoot 고유의 차별점은 **회수가 전투 루프의 필수 요소**라는 점이다. (Brotato/뱀서의 자동 사격, PengPong의 캐주얼 회수와 달리, 이 게임에서 회수는 생존을 위한 능동적 선택이다.)

## 2. 핵심 플레이 루프

1. 탄환을 장전한다.
2. 적을 향해 사격한다.
3. 탄환이 적, 벽, 바닥 등에 박힌다.
4. 탄환을 회수한다.
5. 회수한 탄환을 다시 장전한다.
6. 적을 처치하고 다음 전투로 이동한다.
7. 전투 후 업그레이드를 선택한다.
8. 더 강한 적과 전투한다.

### 플레이어가 매 순간 마주하는 선택

- 이 탄환을 **어디에** 쏠 것인가? (회수하기 쉬운 위치인가?)
- 지금 회수하러 가도 **안전한가**?
- 적을 **빠르게 처치**할 것인가, 회수하기 좋은 위치에서 **끌면서** 싸울 것인가?
- 어떤 **업그레이드**로 회수/사격을 강화할 것인가?

## 3. 주요 시스템

### 3.1 탄환 — 공통 원칙

모든 탄환이 공통으로 따르는 규칙. 개별 탄환의 스탯(속도·수명·관통 여부·튕김 감쇠·피해 등)은 **발사한 무기가 정의**한다 ([7. 무기 시스템](#7-무기-시스템) 참조).

- 탄환은 **발사 후 사라지지 않고** 월드에 남는다.
  - 적에게 박힘
  - **맵 가장자리(벽)에 부딪히면 튕긴다** — 핀볼처럼 궤도가 이어짐
  - 속도가 일정 이하로 떨어지면 바닥에 정지
- 플레이어가 탄환에 접근하면 회수할 수 있다.
- 탄환은 **월드 오브젝트**이며 시야에 명확히 보여야 한다. (가시성이 재미의 핵심)

### 3.1.1 스테이지 구조

- **영역 제한 필드** (Brotato 방식) — 뱀서처럼 무한 스크롤하지 않는다.
- 플레이어는 정해진 사각/원형 아레나 안에서 전투.
- 맵 **가장자리 = 튕김 벽**. 탄환은 필드 밖으로 나가지 않고 벽에 튕겨 다시 필드로 돌아온다.
- 이 구조가 만드는 것:
  - **모든 탄환은 반드시 회수 가능한 위치에 남는다** (필드 밖으로 유실되지 않음)
  - 벽을 이용한 **의도적 튕김 사격** 전략 성립
  - 뱀서라이크의 밀도감을 **좁고 명확한 공간**에서 재현

### 3.2 탄환 회수

- 회수한 탄환은 다시 장전할 수 있다.
- **MVP 회수 방식**: 탄환에 접근 → 자동 회수
- (확장) 회수 범위 증가, 자동 회수 확률, 회수 속도 등을 업그레이드로 추가

### 3.3 전투

- 적은 플레이어를 추적하거나 공격한다.
- 플레이어는 **제한된 탄환**을 효율적으로 사용하면서 적을 처치한다.
- 동시에 발사된 탄환을 **회수해야** 지속 전투가 가능하다.
- **탄환이 0이 되면?** — 회수하러 가거나, 회피에 집중해야 한다. (탄환 부족 = 긴장감)

### 3.4 로그라이크 성장

전투/스테이지 클리어 후 무작위 업그레이드를 선택한다. 성장은 **두 축**으로 구성되며, 조합이 빌드 다양성을 만든다.

- **무기 축 (개별)** — 새 무기 획득 또는 보유 무기 강화. 상세는 [7. 무기 시스템](#7-무기-시스템).
- **공통 축** — 무기와 무관하게 캐릭터·탄환·회수에 두루 적용되는 능력.

**업그레이드 예시**

| 카테고리 | 예시 |
|---------|------|
| 무기 | 새 무기 획득 (슬롯 확장 포함), 공격력 증가, 발사 속도 증가, 최대 탄약 증가 |
| 공통 | 이동 속도, 최대 체력, 회수 범위, 회수 속도, 탄환 잔류 시간, 튕김 감쇠 감소, 튕김 시 피해 증가, 회수 시 체력 회복, 확률적 자동 회수, 회수 시 이동속도 증가 |

> 무기 축은 **어떻게 싸울지**를, 공통 축은 **캐릭터와 탄환 시스템의 기반**을 강화한다.

**확장 방향 (Phase 매핑)**

- **Phase 3** — 무기 축만 도입. 로그라이크 흐름(웨이브 반복·업그레이드 선택 UI)과 무기 획득/강화를 함께 검증.
- **Phase 4+** — 공통 축 확장, 폭발형 무기 등 추가. "무기 조합 + 무기 강화 + 공통 업그레이드"의 복수 축 빌드 시스템으로 완성.

## 4. MVP

### 목표

> **"탄환을 쏘고, 주워서 다시 쏘는 것이 실제로 재미있는가?"**

를 검증하는 것이 MVP의 최우선 목표다.

### 필수 구현

**플레이어**
- 이동 / 조준 / 사격
- 탄환 장전 / 탄환 회수

**탄환**
- 발사 / 충돌 / 월드에 잔류 / 회수 가능 / 재장전 가능

**적**
- 기본 적 1종
- 플레이어 추적 / 피격 / 사망

**전투**
- 제한된 탄환
- 적 처치 → 탄환 회수 → 반복 전투

**스테이지**
- 영역 제한 아레나 1개 (사각형)
- 가장자리 벽 = 탄환 튕김 벽
- 적 웨이브
- 웨이브 클리어 조건

### MVP에서 제외

- 다양한 무기 (아래 [7. 무기 시스템](#7-무기-시스템) 참조) / 다양한 탄환 종류
- 복잡한 로그라이크 메타 성장
- 상점 / 보스 / 스토리
- 복잡한 맵 생성
- 온라인 기능
- 고품질 아트

## 5. MVP 테스트 기준

다음 질문에 **YES**가 나오면 다음 개발 단계로 넘어간다.

| # | 검증 질문 |
|---|----------|
| ① | 탄환이 바닥에 떨어져 있는 것이 실제 게임 플레이에 의미가 있는가? |
| ② | **탄환을 회수하기 위해 이동하는 것이 귀찮음보다 재미가 큰가?** |
| ③ | 탄환을 어디에 쏠지 고민하게 되는가? |
| ④ | 탄환이 부족할 때 긴장감이 발생하는가? |
| ⑤ | 적을 공격하는 것과 탄환을 회수하는 것 사이에 의미 있는 선택이 발생하는가? |

**특히 ②가 중요하다.** 탄환 회수가 단순한 청소 작업처럼 느껴진다면 시스템을 수정해야 한다.

### ②에 대한 수정 방향(참고)

- 회수 자체에 **보상감** 부여 (사운드/이펙트/즉시 재장전)
- 회수 이동 중에도 **의미 있는 위험**이 존재하도록 적 배치
- 회수를 **전략적 선택**으로 만드는 업그레이드 조기 도입
- 자동 회수 요소로 청소감을 줄이되, **자동화가 재미를 빼앗지 않도록** 균형 조절

## 7. 무기 시스템

Phase 3 도입. Phase 2까지는 **권총만** 사용한다.

**무기 = 사격 방식 + 그 무기가 발사하는 탄환의 정의.** 각 무기는 자신의 쿨다운·탄창뿐 아니라 발사하는 탄환의 스탯(속도·수명·관통 여부·튕김 감쇠·피해 등)까지 함께 정의한다. 탄환의 공통 원칙(월드 잔류·튕김·회수)은 [3.1](#31-탄환--공통-원칙)을 따른다.

### 7.1 핵심 규칙

- **다중 보유·동시 운용** — 플레이어는 여러 무기를 동시에 보유하며, 하나의 사격 입력으로 모든 무기를 함께 운용한다. 무기 교체·판매 개념은 없다.
- **무기별 독립 쿨다운** — 사격 버튼을 누르고 있는 동안 각 무기는 자신의 쿨다운이 준비되는 즉시 자동 발사된다. 모든 무기가 동시에 발사되는 것이 아니다.
- **발사 우선순위** — 동일 프레임에 여러 무기의 쿨다운이 준비된 경우: (1) 가장 오래 기다린 무기 → (2) 무기 슬롯 순서. 결정론적 처리.
- **글로벌 최소 발사 간격** — 무기 종류에 관계없이 어떤 두 발사 사이에도 최소 간격(튜닝 대상, 초기 0.1s)을 둔다. 여러 무기가 동시에 준비되어도 이 간격만큼 씩 벌려서 순차 발사되며, 시각·청각적으로 "동시 사격" 느낌 대신 리듬감 있는 캐스케이드가 된다. 단일 무기 쿨다운이 이 간격보다 짧아지지 않도록 강화 상한도 이 값을 하한으로 삼는다.
- **공격 중단** — 버튼을 놓으면 즉시 사격이 멈추지만 진행 중인 쿨다운은 유지된다. 다시 누르면 이어서 진행. → 플레이어가 화력 집중·중단 타이밍을 능동 제어.

### 7.2 무기 슬롯

- **시작 슬롯 1** (권총 1자루). 러닝 중 새 무기를 획득하면 슬롯이 하나씩 확장되며, **최대 4까지** (튜닝 대상).
- 새 무기 획득 = **슬롯 확장 + 신규 무기 배치**가 한 번에 이뤄진다. 별도의 "슬롯만 확장" 선택지는 없다.
- 슬롯이 늘어날수록 화력이 증가하지만, 전장에 생성되는 **탄환의 종류와 양이 함께 증가**한다. 즉 무기 추가는 곧 **탄환 회수 난이도의 증가**로 이어진다.
- 화력과 회수 부담 사이의 tradeoff가 슬롯 확장의 핵심 긴장감.

**무기 시각화 — 조준 방향 부채꼴 배치** (Brotato 방식 참고):

- 각 무기는 플레이어와 독립된 오브젝트로 플레이어를 중심으로 한 **일정 반경의 호(arc)** 위에 배치된다.
- 무기는 **조준 방향 중심의 부채꼴(fan)**로 배치된다. 360° 균등 분포가 아니라 **조준 방향 쪽으로 쏠려** 위치한다.
- 부채꼴 총 각도는 자루 수에 따라 **sub-linear**로 확장된다: 자루가 추가될 때마다 arc는 늘어나지만 1자루당 증가폭은 점차 감소한다 (튜닝 대상). 즉 자루가 많아질수록 무기 사이 간격은 좁아진다.
- 총 arc가 결정되면, 자루 수만큼 그 범위 내에서 **대칭 균등 분포** (1자루 → 정면, n≥2 → −arc/2 ~ +arc/2).
- 조준 방향이 회전하면 부채꼴 전체가 함께 회전한다.
- 발사 방향은 **모든 무기가 동일하게 조준 방향과 평행**. 무기 위치에 따른 수렴/발산은 없다.
- 각 무기의 발사 지점(muzzle)은 해당 무기 오브젝트의 위치.

### 7.3 무기 획득과 강화

전투 보상으로 새 무기 획득 또는 기존 무기 강화 선택지를 제공한다.

- **빈 슬롯이 있을 경우** → 새로운 무기 획득과 보유 자루 레벨업이 선택지에 혼합 제시된다. 이미 보유한 종류라도 새 슬롯에 별도 자루로 추가 가능(각자 독립된 탄창·쿨다운·레벨). 같은 무기 다수 보유 = 화력↑ + 회수 부담↑ tradeoff의 또 다른 축.
- **슬롯이 가득 찬 경우** → 보유 자루 중 하나를 레벨업하는 선택지만 제시된다.

**강화 = 레벨업 단일 축** — 무기별 고유 특성(산탄 수·관통 횟수 등)의 개별 강화는 도입하지 않는다. 강화는 오직 **자루 단위 레벨업** 하나이며, 레벨업 시 3항목이 동시에 상승한다.

- 공격력 ×1.5 (누적 곱셈)
- 쿨다운 ×0.75 (누적 곱셈, 발사속도 ≈ +33%)
- 최대 탄약 +2 (누적 합)

레벨은 **자루 단위**로 관리된다 (종류 단위가 아님). 같은 종류 다수 자루를 보유한 경우 각 자루가 독립된 레벨을 가지며, 레벨업 카드는 대상 자루(슬롯 번호)를 명시한다. 새로 획득한 무기는 Lv.1로 시작한다.

**핵심 선택**: 새 공격 방식(새 무기)으로 화력·회수 부담을 함께 늘릴 것인가, 기존 자루를 레벨업해 특화할 것인가?

### 7.4 탄약 규칙

- 각 무기는 **독립된 탄창**을 가진다. 무기 간 탄약은 공유되지 않는다.
- **1회 사격 = 발사되는 탄환 수만큼 탄약 소비.**
  - 권총·라이플: 1발 발사 = 1 소비.
  - 산탄총: 1회 사격 = 3발 발사 = 3 소비.
- 필요한 탄약이 부족한 무기는 그 프레임에 발사 스킵. (예: 산탄총 탄약 2 남았을 때 발사 스킵)
- 산탄총 탄창은 사격 단위와 맞추기 위해 3의 배수 권장(예: 6/9).

### 7.5 탄환 귀속과 회수

- 발사된 탄환은 **자신을 발사한 무기에 귀속**된다. 튕김·잔류 규칙은 무기와 무관하게 공통.
- 회수 시 **귀속된 무기의 탄창**으로만 충전. 다른 무기 탄창에는 들어가지 않는다.
- 1회 사격에 소비된 탄약 수 = 필드에 생성된 탄환 수이므로, 회수 상한은 자연스럽게 발사량에 맞춰짐. (별도 초과 처리 불필요)

### 7.6 초기 무기 3종

| 무기 | 쿨다운 | 탄창 | 사격 방식 | 탄환 특성 | 회수 루프에서의 성격 |
|------|-------|------|----------|----------|---------------------|
| **권총 (Pistol)** | 짧음 | 큼 | 1발 발사 | 표준 속도·수명·피해. 기준값. | 균형형. 탄환 관리가 가장 명확. |
| **산탄총 (Shotgun)** | 김 | 3의 배수 | 3발 부채꼴 (각 발이 개별 탄환 인스턴스) | 감쇠 빠름·사거리 짧음. 근접 위력 집중. | 필드에 흩뿌려짐 → 회수 지점 분산. 근접 화력 vs 회수 부담. |
| **라이플 (Rifle)** | 중간 | 매우 작음 | 1발 발사 | 고탄속·관통(적 통과 후에도 진행)·고피해. | 발당 효율 최고 → 신중한 사격, 회수 우선순위 명확. |

- 구체 수치는 튜닝 대상.

### 7.7 스코프 밖 / 백로그

- **폭발형 무기(로켓런처 등).** 도입 시 규칙: 적/벽 적중 → 해당 지점에서 폭발(범위 피해) → 탄환 인스턴스는 그 지점에 정지·잔류(회수 대상). 튕김·회수 규칙은 공통.
- **무기 획득 경로 상세** (드랍/상점/선택 UI, 리롤/스킵 등). Phase 4 구체화 시점에 결정.
