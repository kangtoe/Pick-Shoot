# 게임 소개·플레이 영상 만들기 — 연출 원칙 · 촬영 · 편집 · 공개

게임 저장소(README)에 붙일 짧은 소개 영상(트레일러)과 플레이 영상을 만드는 방법. **무엇을 어떻게 보여 줄지**(연출)와 **어떻게 찍고 붙이고 올리는지**(기술)를 함께 적는다. 연출 쪽이 시안을 가장 많이 갈아엎었으므로 앞에 둔다.

> 원본: Pick&Shoot 저장소 `Docs/Guides/GameVideoProduction.md`. 프로젝트 의존 내용이 없으므로 다른 게임 프로젝트에는 이 파일을 그대로 복사해 쓴다. 개선점이 생기면 원본에 반영한다. 촬영 도구 자체는 [AutoPlayRecording](AutoPlayRecording.md).
> 적용 예: Pick&Shoot 소개 영상(2026-10-15, 67.5초, 시안 v1 → v9). 시안별 경위는 그 저장소의 `Recordings/intro_video_2026-10-15.md`.

- 도구: ffmpeg(3.2.2에서 확인 — `xstack`·glob 입력 없음), Python 3 + Pillow, 녹화는 엔진 안 녹화기(Unity면 AutoPlayRecording). 편집기 프로그램 없이 스크립트 하나로 다시 빌드한다 — 고칠 때마다 장면 시각·문구만 바꿔 2~8분 안에 새 시안이 나온다.

## 1. 일하는 방식

- **소리는 사람이 듣는다.** AI 작업자는 소리를 들을 수 없다 — 곡 고르기와 소리 확인(이음매·효과음 크기)은 사람 몫이고, 작업자는 후보 찾기·템포와 음량 측정·박자 맞추기를 맡는다. 시안을 넘길 때마다 "들어 볼 곳"을 시각과 함께 적는다.
- **첫 시안을 빨리, 그다음 고친다.** 구성안을 오래 다듬는 것보다 한 번 보고 고치는 쪽이 빨랐다(9번 고침). 고칠 점이 여럿 쌓이면 **임시 작업 문서**(항목마다 `> 메모:` 줄과 `[ ]` 안 고르기)를 만들어 같이 고친다.
- **안이 갈리면 목업부터.** 같은 장면에 안 넷(예: 자막 처리 방식)을 실제 프레임으로 합성해 한 장에 나란히 보여 주면 빌드 없이 고를 수 있다. 안 이름도 게임 글꼴로 적는다.
- **기록을 남긴다.** 시안마다 무엇이 바뀌었고 왜인지 작업 문서에 한 줄씩. 같은 지적이 되풀이되는지 보인다.
- **끝나면 정리한다.** 편집 중간본·옛 시안·안 쓴 촬영본과 음원 후보는 지우고(Pick&Shoot은 2.8GB → 0.8GB), 최종 빌드 스크립트·그것이 쓰는 촬영본·작업 문서·문서가 가리키는 목업만 남긴다. 영상은 무거워 저장소에는 공개본만 넣는다.

## 2. 연출 원칙

### 2.1 음악이 뼈대다

- 곡을 먼저 정하고 **구간**(도입·쌓아 올림·드롭·본 구간·잠잠·끝 타격)을 잰다. 컷은 마디·박에 맞추고, 화면의 기세를 곡의 기세에 맞춘다.
- **잔잔한 도입에는 잔잔한 화면.** 첫 시안은 0초부터 혼돈 장면과 플래시를 넣었다가 "곡이 잔잔하게 시작하니 화면도 잔잔하게"로 고쳤다 — 빈 필드에 혼자 선 캐릭터 → 첫 사격 → 줍기로 천천히 쌓고, **혼돈은 드롭에서 처음 터뜨린다**. 쌓아 올리는 2마디는 컷 간격을 점점 줄여 드롭으로 끌고 간다.
- 길이는 곡에 맞춘다. 정해 둔 길이(1분)에 얽매이지 말라는 피드백이 있었다 — 곡의 조용한 구간만 건너뛰고(같은 박자 자리끼리 12ms 크로스페이드로 잇는다) 곡의 **끝 타격에 엔드 카드**를 맞췄다.

### 2.2 글자와 영상을 나눈다

- 게임 화면 위에 자막을 얹으면 HUD·피해 숫자·팝업과 겹쳐 읽기 어렵다. 레터박스·흐리기·자막 카드·혼합 안을 목업으로 비교한 끝에 **글자는 어두운 바탕 카드에 따로**(한두 박), **장면에는 글자 없이** 가 됐다. 장면은 HUD와 피해 숫자를 끄고 찍는다.
- 카드 문구는 **기능 이름이 아니라 명령문·짧은 구**: `SHOOT.` → `PICK UP.` → `SHOOT AGAIN.`, 개조는 `EXPLOSIVE` 대신 `BLOW THEM UP.`·`OFF THE WALLS.`·`NEVER MISS.`·`RIGHT THROUGH.` 제목 낱말(PICK·SHOOT)을 돌려 쓰면 영상이 하나로 묶인다.
- **숫자 자랑은 빼라**는 피드백 — `12 GUNS. ONE TRIGGER.` → `LET IT RAIN.`
- 뜬금없는 단어 카드는 실패한다 — `SERPENTS.`(적 이름만)는 "생존·포위·보스 같은 상황"으로 바꾸라고 해서 `SURROUNDED.`가 됐다.
- 글꼴은 **게임 UI 글꼴**(비트맵이면 자산에서 직접 디코드해 찍는다)으로, 핵심 낱말에만 색. 제목 글꼴에서 어색한 글자는 바꾼다(Kenney Blocks의 `&` → `N`, `PICK N SHOOT`).

### 2.3 작위적인 장면을 쓰지 않는다

- 효과를 또렷이 보이려고 **적을 세워 두고(고정·정지) 가만히 서서 쏘는** 장면을 찍었더니 "데모 같다", "무엇을 보여 주는지 모르겠다"였다. **기능마다 카드 한 장씩** 짚는 구성도 설명서처럼 보였다.
- 통과한 방법: **실제 판에서 같은 빌드로 찍고 효과가 잘 보이는 순간을 고른다.** 연출이 꼭 필요하면 **자연스럽게** — 예: 탱커 다섯이 한 줄로 걸어오게 내보내면(고정 없음) 관통 탄이 그 줄을 따라 앞에서 뒤로 쓰러뜨린다.
- 소개 영상은 **"이것저것 많다"는 인상**만 준다. 캐릭터·개조는 카드 한 장 + 실제 판 컷 1~1.5초씩 빠른 몽타주로 압축했고, 시스템별 설명은 플레이 영상과 README로 넘겼다.
- 컷마다 "이 컷은 무엇을 보여 주나?"에 답이 있어야 한다. 캐릭터 능력 시험용으로 찍은 컷(무기 하나 + 큰 적 고리)을 클라이맥스에 섞었다가 지적받아 뺐다.

### 2.4 효과는 끝까지 보여 준다

- 컷 길이를 **효과마다 다르게**. 모두 1초로 맞췄더니 저격은 "쏘고 맞기 직전에 끊겨" 어색했다 — 쏜 순간부터 맞을 때까지(관통이면 줄이 다 쓰러질 때까지) 잡는다.
- 범위 효과는 화면 곳곳에서 일어나게 — 폭발 탄은 조준을 돌려 사방으로 쏘면 벽·적 여기저기서 터진다.
- **시연 장면은 확대하지 않는다**(맥락이 사라진다). 확대는 화면이 비어 작은 대상을 보여 줄 때만.
- **슬로 모션에 소리까지 느려지면 이상하다.** 넣으려면 녹화 때 게임 속도를 늦춰 부드러운 원본을 얻고 소리는 따로 설계한다. 음이 내려가는 효과음(저음 다운)도 느려지는 소리로 들린다.

### 2.5 순서와 일치

- 카드가 말한 것만 다음 장면에 나와야 한다. `SHOOT.` 뒤 장면에 줍기가 섞여 있다는 지적 → "혼자 서 있기 → 사격만 4초 → 줍기"가 확실히 갈리는 촬영으로 다시 찍었다.
- 지루한 기능은 더 센 장면으로 바꾼다 — 수집형 적이 탄을 훔쳐 가는 장면은 "박진감이 없다"여서 큰 적(울트라)이 큰 예고 마커와 함께 내려앉는 장면으로 바꿨다.

### 2.6 시안별로 바뀐 것 (Pick&Shoot 소개 영상)

| 시안 | 고친 것 | 계기 |
|---|---|---|
| v1 | 콜드 오픈 혼돈 → 제목 → 기능 자막 → 엔드 카드 | 구성안 그대로 |
| v3 | 도입 잔잔하게, 글자·영상 분리(명령 카드), 캐릭터 셋, 슬로 모션 뺌 | 잔잔한 곡에 시끄러운 화면, 자막과 게임 글자 겹침 |
| v4 | 개조 구간(같은 무기 12 + 같은 개조), 서펜트 포위, 곡 본 구간 2 전체 | 개조 소개 요청, `SERPENTS.` 뜬금없음 |
| v5 | 개조 카드를 명령문으로, 개조 장면 확대 해제, 도입 재촬영, 탄 훔치기 → 큰 적 | 확대·이름 나열·순서 불일치·박진감 |
| v6 | 고정 적으로 개조 효과 연출, 캐릭터별 카드 | 개조가 너무 빨라 특성이 안 보임 |
| v7 | 캐릭터·개조를 카드 없는 실제 판 몽타주로 | v6이 작위적 |
| v8 | 개조 컷 길이를 효과별로, 폭발은 사방 사격 | 모두 1초라 저격이 끊김 |
| v9 | 관통은 걸어오는 적 줄, 클라이맥스는 실제 판만, `LET IT RAIN.`, 휙 소리 타이밍 | 정지 표적, 숫자 강조, 소리가 이름 |

## 3. 촬영

엔진 안 녹화기와 자동 플레이 봇으로 찍는다(Unity: [AutoPlayRecording](AutoPlayRecording.md)). 영상용으로 봇에 더하면 좋은 옵션 — 한 번 만들어 두면 장면 하나가 요청 파일 한 장이다.

| 필요한 것 | 옵션 예 | 쓰는 곳 |
|---|---|---|
| HUD·피해 숫자 끄기 | `hud=0` | 글자 없는 장면 (README 스틸은 HUD를 켜고 따로 찍는다) |
| 캐릭터·시작 무기·빌드 고정 | `character`, `start_weapon`, `build_weapons`, `build_mods`, `weapons`, `level` | 같은 무기 여러 자루 + 같은 개조 |
| 웨이브 건너뛰기 | `skip_to` | 후반 혼돈 (건너뛰기마다 보상 화면을 거쳐 느리다 — `seconds` 넉넉히) |
| 적 스폰 멈춤 / 종류·수·등급 지정 소환 | `spawns=0`, `spawn=<적>:N`, `spawn_rank`, `spawn_delay` | 빈 필드 도입, 큰 적 장면 |
| 적 배치 | `ring`(포위), `line`(줄), `block`(덩어리), `freeze`(정지 — 작위적이 되기 쉬움) | 포위, 관통 |
| 조준 방식 | `aim=spin`(사방), 쏘기·줍기를 번갈아 하는 시나리오 | 범위 효과, 핵심 루프 |
| 플레이어 화면 좌표 기록 | `track=1` → CSV | 플레이어를 따라가는 확대 크롭 |
| 시드 | `seed` | 같은 판 다시 찍기 |

- 장면은 **촬영본 여러 개를 먼저 찍어 두고 편집에서 고른다.** 한 장면에 10~60초를 찍고 좋은 1~3초를 쓴다.
- 사람이 다른 일을 하는 동안 찍으려면: 에디터 창을 포커스 없이 최소화하고, 스크립트 재컴파일은 요청 파일로, 녹화 중에는 스크립트를 고치지 않는다. 일괄 촬영을 멈추면 셸 프로세스가 남지 않았는지 본다(남은 프로세스가 다음 요청을 써 놓는다). 자세한 함정은 AutoPlayRecording §4.

## 4. 장면 고르기

- **접촉 시트**로 훑는다: `fps=1,scale=320:180,drawtext=…%{pts\:hms}…,tile=12x3`. 고른 구간은 `fps=4`~`15`로 다시 보고, 효과의 시작·끝 프레임을 찾는다.
- 원본 해상도 크롭을 2배 NEAREST로 키워 픽셀 단위로 확인한다.
- 자동으로 찾을 수 있는 것: 보상 화면처럼 어두운 화면은 프레임 평균 밝기(`scale=1:1:flags=area`), 피격 붉은 화면은 평균 R−G가 튀는 프레임. 반복 GIF에 피격 화면이 끼지 않게 피한다.
- 녹화 mp4에 색 태그가 없으면 ffmpeg가 BT.601로 풀어 색이 틀어진다 — RGB로 뽑을 때 `scale=in_color_matrix=bt709`.

## 5. 편집 파이프라인 (ffmpeg + Python)

스크립트 하나가 **타임라인 표**를 읽어 처음부터 끝까지 다시 만든다.

- **구간 종류**: 카드(PNG 정지), 클립(촬영본 + 시작 시각), 몽타주(여러 촬영본의 짧은 조각, 조각마다 길이), 엔드 카드(바탕 + 자막 PNG 오버레이). 구간마다 `fadein`·흰 `flash`·`crop`(확대)·`fadeout` 같은 꾸밈을 붙인다.
- **구간을 따로 굽고 잇는다**: 구간마다 영상(60fps, `-crf 12` 중간본)과 게임 소리(wav, 구간별 음량)를 만들고 concat demuxer로 잇는다 — 목록 파일 안의 경로는 **목록 파일 기준 상대 경로**로 적는다.
- **음악**: 곡에서 두 구간을 잘라 `acrossfade=d=0.012`로 붙이고, 이음매는 반드시 컷 위치에 둔다(스크립트에서 단언). 곡 −3dB, 게임 소리 −8~−12dB.
- **효과음은 타임라인에서 자동 배치**: 카드마다 타격음, 드롭 두 곳에 붐, 엔드 카드에 붐 + 징글. 구성을 바꿔도 어긋나지 않는다. 휙 소리는 **파일 안 정점 위치만큼 앞당겨** 정점이 컷에 오게 한다(정점 0.07초짜리를 0.45초 앞에 두었더니 "너무 이르다").
- **믹스**: 모든 소리를 같은 길이로 `apad`·`atrim` → `amix` → `volume=n`(amix가 1/n로 낮춘 것을 되돌림) → `alimiter`.
- **글자**: 게임 비트맵 글꼴을 자산에서 디코드해 PNG로 찍는다(외곽선·그림자 포함). 오버레이는 RGBA PNG를 `scale=out_color_matrix=bt709` 후 `yuva420p`로.
- **마감**: x264 `-crf 16`, AAC 192k, `-colorspace bt709 -color_primaries bt709 -color_trc bt709`, `-movflags +faststart`.

| 함정 | 해결 |
|---|---|
| `drawtext=fontfile=C:/…` 경로의 콜론이 옵션 구분자로 읽힘 | 글꼴을 작업 폴더에 복사해 상대 경로로 |
| 이미지 glob 입력(`-pattern_type glob`) 미지원 (Windows 빌드) | PIL로 붙이거나 번호 패턴 |
| GIF를 한 번에 `palettegen`+`paletteuse`하면 프레임을 버림 | 두 번에 나눠 실행 |
| 셸 heredoc 안 파이썬 문자열의 `\n`이 실제 줄바꿈으로 바뀜 | 파일로 쓰고 실행, 또는 `splitlines()` |
| 긴 명령이 통째로 실패 (약 8K자) | 스크립트를 파일로 |
| concat demuxer가 목록 안 절대 경로를 목록 폴더에 덧붙여 못 엶 | 목록 파일 기준 상대 경로 |

## 6. 음악·효과음 구하기

- **라이선스를 먼저.** CC0면 표기 없이 쓴다. Freesound API(`license:"Creative Commons 0"` 필터, 키는 파일·메모리에 적지 않고 환경 변수로만), OpenGameArt(페이지의 라이선스 필드 확인 — 사이드바 글자를 잘못 잡기 쉽다), Kenney(CC0 징글). 받은 곳·작가·라이선스를 후보 폴더의 `SOURCES.txt`에 남긴다. GDC 번들류(Sonniss)는 상업 사용·표기 불필요지만 원본 재배포 금지라 저장소에 넣지 않는다.
- 후보는 10개 안팎 받아 사람이 듣게 하고, 작업자는 곡마다 **템포·첫 박 위치·1초 단위 음량**을 잰다(순수 Python으로 RMS → 로그 에너지 상승 → 자기상관). 음량 곡선에서 "조용히 시작했다가 확 터지는" 곡이 트레일러에 맞다.

## 7. 압축·공개 (GitHub)

- 무료 계정 첨부 한도 **10MB**. 1080p가 게임 해상도와 정수 배율이면 **720p보다 1080p가 같은 용량에서 낫다**(축소가 픽셀을 뭉갠다). 2-pass x264 `-preset veryslow -tune animation`: 67.5초 1080p60 990k → 8.7MB, 120초 1080p30 540k → 8.9MB. 같은 용량에서 30fps와 60fps 차이는 거의 없었다.
- **올리기**: 이슈 댓글 입력칸에 mp4를 끌어다 놓기만 하면(등록하지 않아도) `https://github.com/user-attachments/assets/…` 주소가 생긴다. 비공개 저장소의 첨부는 로그인 없이 열리지 않아 작업 세션에서 내용을 확인할 수 없다 — 순서는 사람이 확인한다.
- **README 안 플레이어**: 그 주소를 **한 줄에 혼자**, HTML 블록(`<div align="center">`) 밖에 둔다. GitHub가 플레이어를 **음소거로** 붙이고 README에서는 바꿀 수 없다 → 영상 곁에 "스피커 아이콘을 눌러 켜 주세요" 안내.
- mp4를 저장소에 커밋하지 않는다(100MB 미만이라 LFS 없이 되기는 한다) — README 안 플레이어가 붙지 않고, 지워도 기록에 남아 클론이 계속 무거워진다.
- README 미리보기 GIF는 960x540 15fps 5~6초, 팔레트 64~80색으로 6~7MB. 장면이 붐비면 색 수보다 길이를 줄인다.
- 게임을 고치면(색·등급 등) 이미 만든 README 그림·GIF·영상이 옛 모습으로 남는다 — 바꾼 직후 미디어 목록을 훑는다.

## 8. 시안을 넘기기 전 점검

- [ ] 카드 문구가 명령문·짧은 구이고, 바로 뒤 장면이 그 말만 보여 주는가
- [ ] 장면 위에 글자(HUD·숫자·팝업)가 없는가
- [ ] 정지·고정된 적, 가만히 선 캐릭터가 눈에 띄는 컷이 없는가
- [ ] 효과가 끝나기 전에 끊기는 컷이 없는가, 컷마다 무엇을 보여 주는지 말할 수 있는가
- [ ] 곡의 구간 변화·끝 타격과 화면이 맞는가, 이음매가 컷 위에 있는가
- [ ] 휙·붐 효과음의 정점이 컷에 있는가
- [ ] 사람에게 "들어 볼 곳"을 시각과 함께 적었는가
