# Pick & Shoot — 개발 로드맵

MVP 검증을 최우선으로 하는 단계별 로드맵. 각 Phase는 **핵심 검증 질문**을 통과해야 다음 단계로 진행한다.

---

## Phase 1 — 핵심 프로토타입

> **검증**: "쏘고, 잔류하고, 줍고, 다시 쏘는" 사이클이 실제로 동작하는가?

### 작업

- [x] 플레이어 이동 (2D top-down)
- [x] 마우스 조준
- [x] 사격 (좌클릭)
- [x] 탄환 발사·비행·충돌
- [x] **영역 제한 아레나** (사각형, Brotato 방식)
- [x] **가장자리 벽 튕김** (핀볼식 반사)
- [x] 탄환 월드 잔류 (속도 감쇠 → 정지, 사라지지 않음)
- [x] 탄환 회수 (접근 시 자동)
- [x] 재장전 (회수한 탄환으로 즉시 사용 가능)
- [x] 최대 탄환 수 제한 (예: 6발)

### 통과 조건

- 탄환이 시각적으로 명확히 인지된다.
- 회수·재장전이 매끄럽게 이어진다.
- **"어? 이거 재밌을 것 같은데?"** 라는 감각이 생긴다.

### 산출물

- 빈 방 하나 + 벽 + 플레이어 + 탄환 시스템

---

## Phase 2 — 전투

> **검증**: 탄환 회수가 전투와 결합될 때 의미 있는 선택이 발생하는가?

### 작업

- [x] 기본 적 1종 (플레이어 추적)
- [x] 적 피격 / 사망 (HP·넉백·히트 플래시·명중 후 탄환 감속)
- [x] 플레이어 체력·피격 (무적 시간·데스 화면·R키 재시작)
- [ ] 적 웨이브 (처치 수 기반)
- [ ] 웨이브 클리어 조건
- [ ] 탄환 부족 상태에서의 회피 플레이 성립
- [ ] 기본 사운드 / 피격 이펙트 (피드백 최소치)

### 통과 조건 ([Docs/GDD.md](GDD.md#5-mvp-테스트-기준) 참고)

- ① 탄환 잔류가 게임 플레이에 의미가 있는가
- ② 회수가 귀찮음보다 재미가 큰가 ← **최우선**
- ③ 탄환을 어디에 쏠지 고민하게 되는가
- ④ 탄환 부족 시 긴장감이 발생하는가
- ⑤ 공격 vs 회수의 선택이 발생하는가

**② 통과 실패 시**: 시스템 재설계 후 Phase 2 재검증.

---

## Phase 3 — 로그라이크

> **검증**: 성장 시스템이 핵심 루프를 강화하는가? (덮어쓰지 않고)

### 작업

- [ ] 웨이브 클리어 → 업그레이드 선택 UI
- [ ] 업그레이드 풀 (10~15종)
  - 탄환 카테고리: 관통 / 튕김 / 최대 수 증가
  - 회수 카테고리: 회수 범위 / 자동 회수 / 회수 시 이동속도
  - 사격 카테고리: 피해 / 연사
  - 생존 카테고리: 최대 체력 / 회수 시 회복
- [ ] 웨이브 반복 → 난이도 상승
- [ ] 사망 시 러닝 종료 → 재시작

### 통과 조건

- 업그레이드 선택이 **고민되는가**.
- 특정 빌드가 명확한 **개성**을 만드는가.
- 자동화 업그레이드가 재미를 없애지 않는가.

---

## Phase 4 — 콘텐츠 확장

> **범위**: MVP 검증이 완료된 이후 착수. 순서는 유동적.

### 후보 작업

- 탄환 종류 다양화 (폭발탄, 소이탄 등)
- 적 종류 다양화 (원거리, 돌진, 방패, 소환사 등)
- 무기 다양화 — 권총(표준) / 산탄총(3발 동시) / 라이플(고관통). 자세한 사양은 [GDD 7. 무기 확장 계획](GDD.md#7-무기-확장-계획)
- 보스전
- 맵/방 다양화 (프로시저럴 요소)
- 메타 성장 (러닝 간 유지되는 언락)
- 아트 패스 / 사운드 패스
- 튜토리얼

---

## 백로그 (미분류)

- 탄환 시인성 옵션 (색약 대응)
- 리플레이/데스캠
- 스팀 도전과제
- 로컬 세이브
- 옵션 메뉴 (키 리매핑, 볼륨 등)

---

## 진행 관리

- 각 Phase의 체크박스를 커밋과 함께 갱신.
- Phase 통과 여부는 **본인 플레이 테스트** 또는 지인 플레이 테스트로 판단.
- Phase 실패 시 원인을 GDD의 해당 섹션에 반영하고 재시도.
