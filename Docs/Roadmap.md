# Pick & Shoot — 개발 로드맵

MVP 검증을 최우선으로 하는 단계별 로드맵. 각 Phase는 **핵심 검증 질문**을 통과해야 다음 단계로 진행한다. 예외를 둘 때는 해당 Phase에 이유를 남긴다.

---

## Phase 1 — 핵심 프로토타입

> **검증**: "쏘고, 잔류하고, 줍고, 다시 쏘는" 사이클이 실제로 동작하는가?

### 작업

- [x] 플레이어 이동 (2D top-down)
- [x] 마우스 조준
- [x] 사격 (좌클릭)
- [x] 탄환 발사·비행·충돌
- [x] **영역 제한 아레나** (사각형, Brotato 방식)
- [x] **가장자리 벽 튕김** (핀볼식 반사)
- [x] 탄환 월드 잔류 (속도 감쇠 → 정지, 사라지지 않음)
- [x] 탄환 회수 (접근 시 자동)
- [x] 재장전 (회수한 탄환으로 즉시 사용 가능)
- [x] 최대 탄환 수 제한 (예: 6발)

### 통과 조건

- 탄환이 시각적으로 명확히 인지된다.
- 회수·재장전이 매끄럽게 이어진다.
- **"어? 이거 재밌을 것 같은데?"** 라는 감각이 생긴다.

### 산출물

- 빈 방 하나 + 벽 + 플레이어 + 탄환 시스템

---

## Phase 2 — 전투

> **검증**: 탄환 회수가 전투와 결합될 때 의미 있는 선택이 발생하는가?

### 작업

- [x] 기본 적 1종 (플레이어 추적)
- [x] 적 피격 / 사망 (HP·넉백·히트 플래시·명중 후 탄환 감속)
- [x] 플레이어 체력·피격 (무적 시간·데스 화면·R키 재시작)
- [x] 적 웨이브 (시간 기반, 지속시간 내 지속 스폰 · 종료 시 잔존 적 정리 · 무한 진행)
- [x] 적 스폰 전 경고 (X 아이콘 깜빡임 · 1초 · 근접 시 스폰 건너뜀)
- [x] 감각 튜닝 (벽 반사 강화·각도 제한·이펙트, 적/탄환 상호 분리, 탄환 자석 회수 Lerp, 저속 탄 충돌 무해화, 피격 시 화면 붉은 플래시, 탄환 2단 감속: sustain 후 급감속)
- [x] 피격 이펙트 (Hit 파문·Death 파티클 폭발·Pickup 파문·데미지 숫자: 적 흰색·플레이어 붉은색)
- [x] 탄환 부족 상태에서의 회피 플레이 성립 (자석 회수 완성으로 자연 성립)

### 통과 조건 ([Docs/GDD.md](GDD.md#5-mvp-테스트-기준) 참고)

- ① 탄환 잔류가 게임 플레이에 의미가 있는가
- ② 회수가 귀찮음보다 재미가 큰가 ← **최우선**
- ③ 탄환을 어디에 쏠지 고민하게 되는가
- ④ 탄환 부족 시 긴장감이 발생하는가
- ⑤ 공격 vs 회수의 선택이 발생하는가

**② 통과 실패 시**: 시스템 재설계 후 Phase 2 재검증.

## Phase 3 — 로그라이크 + 무기 시스템

> **검증**: 무기 조합·강화 선택이 서로 다른 플레이 스타일을 만드는가? → **Phase 4로 이월** (아래 통과 조건 참고).

이 페이즈에서는 **무기 축만** 성장 대상으로 도입한다. 플레이어·탄환·회수 공통 축은 Phase 4 이후로 미룬다. 상세 규칙은 [Docs/Systems/Weapons.md](Systems/Weapons.md) 참조.

### 작업

- [x] **다중 무기 시스템** — 슬롯(시작 1, 최대 12), 무기별 독립 쿨다운·탄창, 발사 우선순위, 탄환 귀속·회수 (Weapons §1~§5)
- [x] **웨이브 클리어 → 업그레이드 선택 UI + 무기 획득·레벨업 풀** (Weapons §3)
  - 3택 선택 UI (웨이브 완료 시 게임 일시정지·선택 후 재개)
  - 획득: 새 슬롯에 무기 추가 (동일 무기 중복 허용, 최대 12까지, Lv.1로 시작)
  - 레벨업: 자루 단위 (공격력·발사속도·최대탄약 3항목 동시 상승 — 발사속도 상승은 2026-10-01 제거, 쿨다운은 무기 특성으로 고정)
  - 슬롯이 비어있을 경우 → 획득·레벨업 혼합 제시, 가득 찼을 경우 → 레벨업만 제시
- [x] **초기 무기 3종** — 권총(표준) / 산탄총(3발 동시) / 라이플(고관통, 2026-10-01 저격소총으로 개명) (Weapons §6)
- [x] 웨이브 반복 → 난이도 상승 (웨이브마다 지속 시간·동시 적 수 상한 증가, 적 종류 순차 해금)
- [x] 사망 시 러닝 종료 → 재시작 (Phase 2 데스 화면·R 키 재시작으로 충족)

**완료 (2026-09-18).** 이 페이즈의 의의는 재미 검증이 아니라 **확장 기반 구축**에 둔다 — 무기 축 성장 시스템(슬롯·독립 탄창·귀속 회수·3택 업그레이드)이 무기·적을 늘릴 수 있는 골격으로 서 있다.

### 통과 조건 → Phase 4로 이월

원래의 통과 조건(선택이 고민되는가·조합이 플레이 스타일을 가르는가·화력 대 회수 부담 tradeoff)은 무기 3종·적 3종으로는 조합 공간이 좁아 판단할 수 없다. 판정에 필요한 콘텐츠가 Phase 4의 작업이므로, 검증을 기다리면 Phase 4가 막히고 Phase 4를 하면 검증이 뒤로 가는 순환이 생긴다. 그래서 검증 없이 Phase 3을 닫고, 세 질문은 [Phase 4 검증 체크포인트](#검증-체크포인트-phase-3에서-이월)에서 무기·적을 늘린 뒤 플레이 테스트로 판정한다. Phase 2 ②(회수 재미)를 재검증으로 미룬 것과 같은 성격의 예외다.

---

## Phase 4 — 콘텐츠 확장

> **범위**: Phase 3 기반 구축 완료 후 착수 (2026-09-18~). 순서는 유동적. Phase 3에서 이월한 검증 질문을 이 페이즈 안에서 판정한다.

Phase 3에서 무기 축만 도입한 성장 시스템을 **공통 축**으로 확장한다 ([GDD §3.4](GDD.md#34-로그라이크-성장)). 고정된 작업 목록 대신 아래 [백로그](#백로그)에서 골라 진행한다.

### 검증 체크포인트 (Phase 3에서 이월)

무기·적 추가를 한 차례 마친 뒤 플레이 테스트로 판정한다. 미통과 시 원인을 [Weapons.md](Systems/Weapons.md)·[Enemies.md](Systems/Enemies.md)에 반영하고 재시도.

- 무기 획득/강화 선택이 **고민되는가**.
- 무기 조합이 서로 다른 **플레이 스타일**을 만드는가.
- 화력↑과 회수 부담↑의 **tradeoff**가 실제 긴장감을 만드는가.

  - 픽셀 UI — 업그레이드 카드, HUD(좌상단 체력 핍(2026-10-02 게이지 + 숫자로 교체) · 머리 위 체력 막대 · 하단 양 끝 무기 슬롯 탄약 핍 · 상단 웨이브 배너와 남은 시간 바), 크로스헤어(탄약 링 + 중심점), 데스 화면, ESC 일시정지 화면(카드 선택처럼 정지·HUD 숨김·조준 정지).

- **튕김음·헛방 소리** 추가 (2026-09-18).
- **대시** — 스페이스로 이동 입력 방향(없으면 조준 방향)에 순간 이동, 쿨다운 중 머리 위 원형 표시, 궤적 잔상·효과음, 대시 중 적 통과·피해 무시 (2026-09-21). 규칙은 [GDD §3.5](GDD.md#35-대시).
- **무기별 HUD 개선** — 하단 무기 슬롯의 패널 배경을 걷고 자루마다 한 줄(스프라이트 · 레벨 · 탄창)로 정리, 탄약 핍은 빈틈없이 붙인 탄창 한 덩이로, 오른쪽 구석은 거울상. 함께 무기 레벨 상한을 9(한 자리)로 둬 표기 폭과 탄창 길이를 묶음 (2026-09-22). 규칙은 [Weapons §4](Systems/Weapons.md#4-탄약-규칙).
- **리롤** — 웨이브 클리어 카드 화면마다 한 번 무료로 3장을 다시 뽑는 버튼. 보이는 카드 중 무작위 한 장을 빼고 뽑아 한 장은 반드시 바뀌고, 후보가 카드 수 이하면 버튼을 두지 않음 (2026-09-22, 한 장 제외 방식은 2026-09-24). 규칙은 [Weapons §3](Systems/Weapons.md#3-무기-획득과-강화). 조건은 2026-10-02 처치 스코어 문턱으로, 같은 날 레벨 업 적립으로 바꿈 (아래 경험치·레벨 업).
- **돌진형 적** — 접근·준비·돌진·회복 사이클, 포즈 깜빡임 텔레그래프, 벽 캐스트 정지·플레이어 접촉 시 종료, 웨이브 4 해금 (2026-09-24). 규칙은 [Enemies §4](Systems/Enemies.md#4-돌진형-상세). 적 이동 코드를 공통 골격과 행동으로 나눠 다음 적(원거리형)은 행동만 얹는다.
- **공격 임박 경고** — 공격 직전 구간 동안 적 머리 위에 느낌표. 돌진형 준비 단계에 적용, 원거리형은 발사 직전에 쓸 후보 (2026-09-25). 규칙은 [Enemies §1](Systems/Enemies.md#1-공통-규칙).
- **적 벽 판정** — 모든 적이 아레나 벽을 넘지 않는다. 넉백·분리 힘에 밀려도 벽 앞에서 멈추거나 벽을 따라 미끄러지고, 돌진형은 돌진 중 막히면 회복에 든다 (2026-09-29). 규칙은 [Enemies §1](Systems/Enemies.md#1-공통-규칙).
- **서펜트형 보스** — 머리 + 몸통 마디 사슬. 머리만 조향하고 몸통은 머리의 궤적을 따르며, 몸통을 끊으면 뒤가 분열해 별개의 서펜트가 된다. 5의 배수 웨이브 시작에 등장 (2026-09-29). 규칙은 [Enemies §5](Systems/Enemies.md#5-서펜트형-보스-상세). 그림은 플랫포머 팩의 네모 캐릭터·타일을 외곽선 규칙에 맞춘 사본 ([PixelArtUI §7](Systems/PixelArtUI.md#7-스프라이트-팩과-외곽선-규칙)).
- **방랑형·수집형 적** — 방랑형은 플레이어 근처를 가로질러 벽·화면 가장자리까지 직진하고 거기서 다시 경로를 잡는 움직이는 장애물(경로 지점은 2026-10-01 화면 안 무작위 지점으로 바꿈), 수집형은 흩어진 정착 탄환이 생기면 곧바로 찾아가 곁의 고리에 겹치지 않게 끌어모으고, 든 만큼 느려지며, 탄환이 없으면 방랑형처럼 움직이는 우선 격파 대상. 둘 다 가는 방향을 보고, 웨이브 5·6 해금 (2026-09-30). 방랑형은 2026-10-01 소환사형으로 대체 (아래). 규칙은 [Enemies §6](Systems/Enemies.md#6-수집형소환사형-상세-방랑-이동).
- **소환사형 적** — 방랑 이동(화면 안의 무작위 지점을 향해 벽·화면 가장자리까지 직진)을 그대로 쓰며 짧은 주기마다 그 순간의 자리에 웨이브 스폰과 같은 예고 마커를 띄운 뒤 졸개를 낳는 우선 격파 대상. 쏘는 졸개는 나온 순간의 플레이어 방향으로 직진하다 벽·화면 가장자리에서 죽는 발사체 같은 적이고, 소환사가 플레이어에게 죽으면 같은 그림의 보통 추적형 졸개 셋을 그 자리에 남긴다. 살아 있는 졸개 상한은 소환사마다 세고, 졸개는 독립된 적. 방랑형을 대체해 웨이브 5 자리를 이어받았고, 방랑 이동은 수집·소환사형의 공통 골격으로만 남겼다 (2026-10-01). 그림은 플랫포머 시트의 큰 파란 로봇(소환사)과 작은 파란 로봇(졸개). 규칙은 [Enemies §6](Systems/Enemies.md#6-수집형소환사형-상세-방랑-이동).
- **폭발형 무기 1차** — 런처(Launcher) 1종. 튕김 0의 폭발 탄환 — 첫 접촉 지점에서 반경 피해·넉백 후 그 자리에 정착·잔류. 자해 없음 (2026-09-23). 규칙은 [Weapons §7](Systems/Weapons.md#7-폭발-탄환).
- **추가 무기 1차** — SMG(약한 탄을 큰 탄창으로 빠르게)·라이플(3점사) 2종. 점사는 한 사격 차례에 이어 쏘는 사격 묶음으로, 버튼을 놓아도 끝까지 나가고 그 사이 다른 자루는 기다린다. 기존 라이플(고관통)은 저격소총(Sniper)으로 개명 (2026-10-01). 규칙은 [Weapons §8](Systems/Weapons.md#8-점사)·[§6](Systems/Weapons.md#6-무기-목록).

- **처치 스코어·리롤 문턱** — 플레이어가 적을 죽이면 적별 값(EnemyData)이 러닝 누적 스코어에 더해지고 그 자리에 노란 `+N`이 뜬다. 총점은 HUD 우상단에 (카드 화면에도 같은 자리). 적 피해는 머리 위에 합산 표기(일정 시간 맞지 않으면 초기화·숨김), 플레이어 피격 숫자는 위로 미는 충격 + 직사각형 안 무작위 충격으로 튀어올라 중력·감쇠로 가라앉고(Terraria 전투 텍스트 모델), 스코어는 등속으로 떠오르는 움직임. 리롤은 화면당 한 번 무료에서 "총점이 문턱 이상이면"으로 — 문턱은 10·20 뒤 앞 둘의 합(피보나치식), 러닝 누적, 스코어는 차감하지 않고, 버튼에는 이어서 할 수 있는 횟수만 표기 (2026-10-02). 같은 날 경험치·레벨 업으로 전환 (아래).
- **경험치·레벨 업** — 처치 스코어를 경험치(XP)로. 누적 XP가 문턱(10·20 뒤 앞 둘의 합 — 리롤 문턱 표를 그대로 이관)에 닿을 때마다 레벨 업: 최대 체력 +1·체력 완충·리롤 1회 적립. 리롤은 스코어 문턱 판정 대신 "레벨 업 횟수 − 쓴 횟수". 처치 문구는 `XP N`. HUD는 우상단 총점을 걷고 하단 중앙에 레벨과 구간 게이지(시트의 파란 채움, 숫자 없음)를 두어 상단 중앙 웨이브 바와 짝을 맞췄고, 누적 총량은 일시정지 화면에서만 — 그 화면은 `PAUSED` 배지가 걸린 상태 카드(업그레이드 카드와 같은 결)에 WAVE·LEVEL·XP 표(라벨 왼쪽·값 오른쪽)로 개편. 레벨 업 순간 플레이어 머리 위에 파란 `LV UP!` 플로팅 텍스트 (2026-10-02). 규칙은 [GDD §3.3](GDD.md#33-전투)·[Weapons §3](Systems/Weapons.md#3-무기-획득과-강화).
- **플레이어 스탯·커먼 유물** — 성장 시스템 로드맵 ①. 플레이어 스탯 7개(공격력 배율·이동속도·최대 체력·재생·회수 범위·회수 속도·능력 리차지)를 플레이어의 `PlayerStats`에 유물 수정치의 합으로 두고 없던 둘(공격력 배율·재생)을 신설, 커먼 유물 7종(RelicData 자산 `Assets/Data/Relics`, 임시 열쇠 아이콘 — 2026-10-04부터 유물별 색), 유물 보상 카드 화면(무기 카드와 같은 3택·리롤 공유, `OWNED n → n+1`과 스탯 총계 줄), 웨이브 클리어 보상의 유물/무기 교대(홀수 웨이브 유물·짝수 무기), 디버그 도구의 유물 획득·스탯 총계 (2026-10-03). 규칙은 [Relics §2](Systems/Relics.md#2-커먼-유물)·[GDD §3.4](GDD.md#34-로그라이크-성장). [Relics §5](Systems/Relics.md#5-구현-로드맵)의 확인할 것은 플레이 테스트 대기.
- **일시정지 화면 빌드 표시·글꼴 `.`** — 상태 카드 아래에 보유 무기(HUD와 같은 작은 판 + `LV9`)·보유 유물(아이콘 + `X3`, 처음 얻은 순서) 두 줄(BuildStripPainter, 패널 배경 없음, 글자는 아이콘 옆 — 12자루에 1668px로 16:10까지). 글꼴에 `.` 추가(소수 표기 대비, [PixelArtUI §5](Systems/PixelArtUI.md#5-글꼴과-임시-아이콘)), 단어 단위 줄 접기(PixelGui.WrapText), 무기 판 그리기를 PixelGui로 옮겨 HUD와 공유, 읽는 쪽의 기본값 접근자, 유물 자산에 설명 문구(`description`) 자리 (2026-10-04). 같은 날 보상 화면 개편(아래 진행 예정의 UI 개선)을 구현까지 갔다가 롤백하면서 이것들만 남겼다.
- **무기·유물 타일 표준화와 툴팁** — 무기 한 자루·유물 한 종류를 보이는 곳을 브로타토식 정사각 타일(28×28텍셀, HUD 판과 같은 단색, `ItemTilePainter`) 하나로 통일. 일시정지 화면은 패널 배율 격자(무기 슬롯 12칸 한 줄 — 빈 슬롯도 타일, 유물은 종류별로 12열에 접음), 보상 화면은 리롤 버튼 아래 글자 배율 한 줄(그 화면 종류만 — 세로 여유가 72px뿐이라 간격을 줄여 넣음. 10월 4일 "보상 화면엔 두지 않는다"를 뒤집음: 빈 슬롯으로 남은 슬롯 수가 보이고 툴팁으로 보유 자루와 카드를 비교할 수 있어서), 카드 전시 칸은 같은 타일을 배율 6으로(8이면 카드가 한 타일 자라 블록이 1080을 넘음). 배지는 타일 아래쪽을 가로지르는 외곽선 색 띠의 `L5`·`X3`(`X1`도 표기, 그림은 그 위로 올림), 타일과 카드 전시 칸에 마우스를 올리면 자산 값에서 만든 툴팁(`TooltipPainter` — 내용 크기 패널, 글자 배율 2, 사실 항목은 폭에 맞춰 채워 넣고 설명은 단어 단위로 접음). HUD는 그대로 — 정사각 판·모서리 배지·바탕 없는 배지·배율 1 글자 네 안을 실제 시트로 목업해 보고 전부 제외 (2026-10-06, [PixelArtUI §4](Systems/PixelArtUI.md#4-아이템-타일과-배지)). 무기 자산의 `description`은 아직 비어 있다 — 특성은 수치에서 만든 항목이 대신한다. 같은 날 후속 — 줄마다 위에 브로타토식 제목과 수량(`WEAPONS (7/12)`·`RELICS (5)`, 리롤 버튼과 같은 괄호 꼴, 일반 글꼴 글자 배율, 격자 왼쪽 끝 맞춤)을 두고(수량이 붙어 제목에 쓸모가 생겨 "줄 이름은 두지 않는다"를 뒤집음), 빈 무기 슬롯의 어두운 타일을 걷어 보유 자루만 보이며(남은 슬롯 수는 제목의 `n/12`), 무기 배지는 `L5` → `LV5`(글자 배율 2로 64px라 보상 화면 줄의 타일을 글자 배율 56px에서 배율 3의 84px로 올리고 블록 간격을 줄여 1060px. `LV.5`도 잠깐 썼다가 점을 뺐다). 일반·아웃라인 글꼴 제목과 빈 슬롯 유무를 실제 시트로 목업해 비교해 골랐다.

- **카드 특성 표기·표기 정리** — 무기 카드의 표에 DMG·AMMO 뒤로 그 무기의 수치 특성(`BURST 3`·`BOUNCE 5`·`PIERCE 1`·`BLAST 2.5`)을 같은 줄로 잇고(레벨로 바뀌지 않는 줄은 화살표 없이 값 하나), 수치가 없는 특성(`AUTO RETRIEVE`·`PULLS IN`)만 표 아래 가운데 맞춤 아웃라인 한 줄로 둔다. 유물 카드는 같은 자리에 수정치 한 줄. 무기를 가르는 것이 호버하지 않아도 카드에서 바로 읽힌다 — 10월 6일 타일 툴팁으로 일부 해결했던 "카드가 담는 정보가 적다"(아래 UI 개선 항목)의 나머지. 태그(칩) 대신 글줄로 둔 것은 레퍼런스 카드(스탯 목록 아래 `Piercing`·`Slow` 같은 굵은 한 줄)처럼 표와 같은 흐름으로 읽히게 하기 위해서이고, 칩은 테두리·여백이 세로를 더 먹는다. 함께 **다섯 가지 표기를 뺐다** — RPM(쿨다운·점사에서 역산한 값), 슬롯 번호(`SLOT 3` → 줄 라벨이 `LEVEL`, 값도 `LV 2 → LV 3`에서 `2 → 3`으로), 산탄 각도(발수만), 고정 탄창(`AMMO 1 → 1`이 이미 말한다), 유물 카드의 보유 수 줄(`OWNED 1 → 2` — 전시 배지 `X2`가 이미 말한다. 유물 카드는 이름 밑이 곧 스탯 표다). 다른 데서 이미 보이는 것과 역산한 수를 걷어낸 정리다. 유물 카드는 더 줄였다 — 스탯 값이 `지금 총계 → 획득 뒤 총계`에서 **그 유물이 더하는 수정치 하나**(`DMG +10%`, 양수에도 부호)로 바뀌었고, 설명 문구는 아예 비웠다 — 대신 스탯 이름을 줄임말에서 읽어서 아는 말로 풀었다(`DMG` → `GUN DAMAGE`, `RANGE` → `PICKUP RANGE`, `SKILL` → `RECHARGE`…, 폭 상한 244px). 유물 카드에는 표가 없고 수정치가 `GUN DAMAGE +10%` 한 줄(무기 특성 줄과 같은 가운데 맞춤 아웃라인)로 들어간다 — 한 줄짜리 효과를 좌우로 가르면 눈이 빈칸을 건너야 했다. 타일 툴팁의 `OWNED 3`도 같이 뺐다(배지 `X3`). 유물 자산의 `description`은 스탯 줄이 못 하는 말(유니크의 조건 효과)이 생길 때까지 빈 채로 두고, 비면 예외였던 검사도 걷었다. 유물 카드 목업은 `Recordings/relic_card_mockup_2026-10-07_v2.png` — 내용이 줄어 카드(7×10타일) 아래가 230px 남는다. 자리는 그 RPM 줄과 이름→표 간격 12→8텍셀, 전시 칸의 남는 여백 24px에서 나왔다 — 카드는 7×10타일 고정이고 보상 화면 블록이 이미 세로 1080 중 1060을 써 카드를 키울 수 없다. 획득 카드에서는 비교를 걷어 모든 줄이 값 하나다 — 아직 없는 자루의 `-` 열은 읽을 것이 없었다. DMG의 `X발수`도 점사 수를 빼고 동시 발사 수(산탄)만 곱한다 — BURST 줄과 겹치고, 블래스터 고레벨의 `108X24`는 유물로 공격력이 조금만 올라도 카드 폭을 넘겼다(유물 3개면 벌써 382/368px). 지금 가장 긴 조합은 특성 한 줄 + 본문 한 줄(부메랑·볼텍스)로 아래 여백 72px이고, 12종 전 레벨을 전역 피해 배율 ×3까지 다시 재도 폭·높이 모두 든다. 글꼴 지표로 12종 전 레벨·유물 7종을 미리 재고(가장 긴 줄은 볼텍스 `BLAST 2.5 PULLS IN` 348/368px), 실제 시트로 합성한 목업으로 확인했다 (무기 카드 `Recordings/weapon_card_mockup_2026-10-07_v2.png`, 절차는 [PixelUiMockup](Guides/PixelUiMockup.md)). 규칙은 [Weapons §3](Systems/Weapons.md#3-무기-획득과-강화) (2026-10-07).
- **레벨업 공격력을 고정 가산으로** — 레벨당 공격력이 `×1.5 누적 곱셈`에서 `+기본 공격력`(무기별 `levelDamageAdd`, 12종 전부 기본 공격력과 같은 값)으로 바뀌어 Lv.n의 공격력 = 기본 × n이다. 곱셈은 레벨당 오르는 폭이 뒤로 갈수록 커져 Lv.9가 기본의 25.6배(권총 256)였고 — 한 자루에 레벨을 몰아주는 것이 늘 정답이고 레벨업 한 번의 값이 레벨마다 달라 카드의 `현재 → 다음`으로 가늠하기 어려웠다. 고정 가산은 Lv.9가 9배(권총 90)라 **적 체력·웨이브 난이도와 함께 다시 튜닝해야 한다** (아래 무기 12종 튜닝). 규칙은 [Weapons §3](Systems/Weapons.md#3-무기-획득과-강화) (2026-10-07).
- **보상 화면 배치 개편** — 제목 `WAVE N CLEAR`를 빨간 배너에서 패널 없는 아웃라인 글자(배율 4)로 바꿔 부제와 함께 카드 묶음 왼쪽 끝 위에, 리롤 버튼을 오른쪽 끝 위에 두어 한 띠(96px)로 묶고, 카드 밑에는 무기 줄·유물 줄(배율 3 타일)을 화면 종류와 무관하게 둘 다 카드 왼쪽 끝에 맞춰 둔다 — 유물 화면에서도 보유 자루를, 무기 화면에서도 보유 유물을 본다. 세로로 쌓던 배너(128)·부제·리롤 버튼(88)이 띠로 올라가며 번 자리에 둘째 줄(124 + 간격 16)이 들어갔다 — 블록 1060 → 1048px, 위아래 16px. 배너 패널을 남기면(배율 4) 둘째 줄이 16px 넘쳐 배율 3(96px)으로 낮추는 안도 있었지만 글자만 둔 안이 깔끔해 골랐다. 띠·줄을 캔버스 가장자리가 아니라 카드 묶음에 맞춘 것은 16:10에서도 한 덩어리로 읽히게 하려는 것이고, 줄을 가운데 두면 카드보다 166px 들어가 어정쩡했다. 실제 시트로 여섯 안(현재·배너 배율 3 가운데/왼쪽 정렬·글자 제목·화면 가장자리 기준·유물 화면)을 전체 화면으로 합성해 골랐다 (`Recordings/reward_layout_mockup_2026-10-07.png`, 720p는 `_720`, 절차는 [PixelUiMockup](Guides/PixelUiMockup.md)). 규칙은 [Weapons §3](Systems/Weapons.md#3-무기-획득과-강화) (2026-10-07). 같은 날 후속 셋 — ① 카드·리롤 버튼의 호버 들림(카드 4텍셀·버튼 2텍셀)을 걷고 선택 테두리만 남겼다. 띠가 카드 바로 위로 오면서 들린 카드의 배지가 부제를 가렸다. ② 리롤 버튼은 `REROLL (2)` 한 줄에서 `R` 한 글자(뒤에 리롤 아이콘 자리) 2×2타일 정사각으로, 남은 횟수는 버튼 아래 변에 8px 걸친 수 배지(타일 배지와 같은 외곽선 색 판 + 글자 배율 숫자)로 — 문구 길이에 버튼 폭이 끌려가지 않는다. 버튼 배율은 글자 배율 2(64px)로 넣었다가 띠 안에서 작아 보여 2026-10-08 카드 배지와 같은 3(96px, 띠 높이와 같다)으로 올렸다 (`Recordings/reroll_button_mockup_2026-10-08.png`). 같은 날 다시 — 횟수를 늘어뜨린 수 배지에서 **타일과 같은 아래쪽 띠**로, 버튼 자체도 회색 패널에서 타일과 같은 단색 판(32텍셀 × 3)으로 바꿔 `R`이 띠 위 칸 가운데(중앙보다 위)에 온다 — 다른 아이콘 표시와 같은 꼴. 회색 패널에 띠를 넣는 두 안(테두리 안쪽 띠·전체 폭 띠)도 목업했으나 패널 테두리 6텍셀이 칸을 먹어 `R`이 배율 2로 줄거나 띠가 테두리 베벨을 자른다 (`Recordings/reroll_band_mockup_2026-10-08.png`). 그 뒤 한 번 더 — 일시정지 격자의 타일과 같은 패널 배율 4·28텍셀(112px, 띠보다 커 위아래 8px씩 나옴)로 키웠다 (`Recordings/reroll_tile_mockup_2026-10-08.png`). `R`을 아웃라인 글꼴로 잠시 바꿨다가 일반 글꼴로 되돌리고, 배율 5(획 60px — 띠 위 칸 68px에 드는 최대)로 키웠다가 약간 작게 버튼 배율 4(획 48px)로 (128px 버튼 안과 모서리 2단 깎기 안도 목업 — 모서리는 모든 판이 같은 1텍셀 깎기라 그대로 둠, `Recordings/reroll_corner_mockup_2026-10-08.png`). 에디터에서 0회 버튼의 모서리가 각져 보인 것은 모양이 아니라 **어둡게 덮던 검은 막(직사각형)이 깎인 귀까지 덮어서**였다 — 막을 걷고 판·띠·글자 색에 어둡게 곱하는 방식으로 (`DrawWeaponPlate`·`DrawBadge`에 tint 오버로드). 호버 때는 선택 테두리 9-slice가 모서리 두 장(배율 4면 128px)보다 작은 버튼(112px)에서 예외로 `OnGUI`를 끊어 카드·줄이 사라졌다 — 테두리 배율을 버튼에 드는 값(3, 96px)으로. 둘 다 목업에 비활성·호버 상태를 안 그려 놓친 것 ([PixelUiMockup §5](Guides/PixelUiMockup.md)). 끝으로 카드 패널처럼 버튼 바깥에 1텍셀 흰 선을 둘렀다(`PixelGui.FillPlateShape`) — 누르는 것임을 인벤토리 타일과 가르는 표시. 이번엔 보통·호버·0회를 다 그려 확인했고(`Recordings/reroll_outline_mockup_2026-10-08.png`), 흰 선 위에서 호버 테두리가 묻혀 잠시 배율 4 두 타일(128px)을 버튼 밖으로 냈다가, 카드의 호버는 안쪽이라 흰 선 안쪽 판 영역(104px)에 배율 3으로 옮겼는데(`_v2.png`), 선택 테두리 조각이 괄호가 아니라 2텍셀 흰 띠라 배율 3(6px)으로는 외곽선 8px 중 2px가 어둡게 남아 틈으로 보였다. 결국 **호버 때 판의 외곽선 자체를 흰색으로** 그려 바깥 흰 선과 이어 12px 흰 테두리가 바탕까지 닿게 하고, 띠는 외곽선 안쪽 폭으로 줄여 테두리가 끊기지 않게 했다 (띠 폭 그대로 두는 안과 비교, `Recordings/reroll_hover_mockup_2026-10-08_v3.png`). 리롤 버튼은 이제 선택 테두리 9-slice를 쓰지 않는다. 같은 날 호버를 카드·리롤 모두 "가운데 기준 비정수 배율로 살짝 키우기"(1.06, GUI.matrix 스코프)로 바꿔 봤다가 **되돌렸다** — 에디터에서 텍셀이 4·4·4·5px로 갈리고 글자 쿼드가 따로 반올림되어 깨져 보였고, 아래로도 17px 자라 띠 간격 8px를 넘어 빌드 줄 제목을 덮었다. 정수 배율 원칙([PixelArtUI §1](Systems/PixelArtUI.md#1-기준-캔버스와-배율))의 목적(UI·월드 한 격자, IMGUI 틈)을 따져 예외를 두려 했으나 결과가 말해 줘 원칙 그대로. 잠시 4텍셀 들림으로 돌아갔다가 최종으로 **흰 테두리를 바깥으로 1텍셀 넓히기**(카드·리롤 같은 값, `UpgradeCardPainter.HoverOutlineTexels` — 요소보다 한 텍셀 큰 흰 판 모양을 밑에 깔아 바깥 흰 선이 2텍셀이 된다. 패널·판 모두 모서리가 1텍셀 깎여 있어 그 귀가 메워지고 바깥 귀만 깎인다). 크기·자리가 변하지 않아 부제·빌드 줄 제목을 가리지 않는다. 함께 카드→빌드 줄 간격을 8 → 24px로 벌렸다(줄이 카드에 붙어 보였고 테두리 4px이 나온다) — 블록 1032px, 위아래 24px. 선택 테두리·안쪽 흰 외곽선 호버는 걷었다. ④ 카드를 7×10에서 **7×9타일**로 낮췄다 — 표가 짧은 카드(산탄총·유물)의 아래가 비어 보였다. 카드 안 줄 간격(전시→이름·레벨→표·이름→레벨)을 8→6텍셀로 줄여 가장 긴 카드(볼텍스·부메랑)도 아래 여백 48px을 지킨다. 번 64px 중 32를 띠→카드 간격에 더해(40→72px) 카드를 띠에서 뗐다 — 블록 1048→1016px, 위아래 32px (같은 목업). ③ 무기 카드의 수치 없는 특성 줄(`PULLS IN`·`AUTO RETRIEVE`)을 표 아래 가운데 맞춤 아웃라인에서 표의 마지막 줄(일반 글꼴)로 — 앞의 16px 간격도 뺐다. 값 열 오른쪽 정렬로 넣었다가 2026-10-08 라벨 열 왼쪽 정렬로 (라벨을 읽던 눈이 오른쪽으로 건너뛰어야 했다) (유물 카드의 수정치 줄은 표가 없어 가운데 맞춤 그대로, 글꼴만 2026-10-08 일반으로 — 카드에서 아웃라인은 이름뿐). ②·③은 `Recordings/reroll_button_mockup_2026-10-07.png`.
- **카드 머리 가로 배치** — 업그레이드 카드의 전시 타일을 왼쪽으로 밀고 그 오른쪽에 종류 제목(`NEW`·`LV UP`·유물은 등급 `COMMON`, 일반 글꼴)과 이름(아웃라인 배율 2) 두 줄을 두는 브로타토식 머리로 (2026-10-08). 종류를 카드 위 끝에 걸치던 배지(노란 `NEW!`·파란 `LV UP`)는 걷고, 그 그리기는 일시정지 화면의 `PAUSED` 탭에만 남겼다. 새 무기만 제목이 XP 팝업과 같은 노랑(`PixelUiSkin.HighlightText`) — 색 패널(카드 안에서 버튼처럼 보임)·외곽선 색 띠(머리가 번잡) 안과 실제 시트로 비교해 골랐다 (`Recordings/card_header_mockup_2026-10-08.png`·`_v2.png`, 720p 크롭 `_v2_720.png`). 타일 오른쪽 칸이 240px이라 전시 타일은 배율 6 → 4(일시정지 격자와 같다), 이름은 배율 3 → 2 — 가장 긴 `ARMOR PLATE`(234px)가 든다. 머리가 240 → 112px이 되어 카드는 7×9 → 7×7타일, 띠→카드 간격은 배지가 없어져 72 → 40px(블록 1032 → 872px). 한 장이 레벨을 둘 이상 올리는 보너스 카드는 아직 없지만 자리를 만들어 뒀다 — `UpgradeOption.Levels`(지금은 전부 1)가 2 이상이면 제목이 `NEW (+n)`·`LV UP (+n)`이고 표·배지·툴팁·적용이 그 레벨을 따른다. 같은 날 2차 — 제목을 글자 배율 2에서 3으로 키우고(꼬리 `(+n)`은 배율 2로 글리프 상자 아래 변을 맞춤 — 배율 3이면 `LV UP (+2)`가 글자 칸을 넘는다), 이름은 200px에서 낱말 단위 두 줄로 접으며(`ARMOR PLATE`), 왼쪽에 붙던 타일·글자 묶음을 카드 가운데로 (`Recordings/card_header_mockup_2026-10-08_v3.png`). 머리 높이는 두 줄 기준 120px 고정이라 표의 시작 줄이 카드마다 같다. 3차(2026-10-09) — 유물 카드도 제목을 노란 `NEW`로 하고, 등급은 무기 카드의 레벨 줄 자리에 `GRADE COMMON` 한 줄로(값 열, 등급 색). 거기까지 가며 이름 밑에 부제 줄(유물 `COMMON`·무기 `LEVEL +1`, 보너스 꼬리 `(+n)` 대신)을 두고 표의 레벨 줄을 빼는 안, 부제를 머리 밑 따로 - **글자 간격 조정** — 시트 글꼴의 letterSpacing을 1에서 −1로 (spaceWidth 5 유지). 글자 상자가 한 열을 겹쳐 획 사이가 5에서 3텍셀로, 낱말 틈은 9에서 7텍셀로 조여진다. 같은 날 Kenney Pixel 글꼴 교체와 무기 레벨 로마 숫자를 구현해 봤다가 목업 비교 뒤 롤백했다 (2026-10-08). 규칙은 [PixelArtUI §5](Systems/PixelArtUI.md#5-글꼴과-임시-아이콘).

- **무기별 색** — 6종마다 고유한 색 하나를 총 그림의 강조색·탄환·총구 화염이 함께 쓴다 (권총 금색·SMG 분홍·저격소총 파랑·라이플 주황·런처 초록·산탄총 빨강). 총 그림은 시트 주황 세트의 강조색 세 단만 무기 색으로 바꾼 사본 `Assets/Art/Sprites/weapons_colored.png`이다. 그전에는 탄환·화염만 무기별 색이고 총 그림은 시트 그대로라 서로 맞지 않았다. 한 색 통일·총 그림 두 계열·무기별 색(탄환 키우기 유무)을 목업으로 비교해 무기별 색 + 그림 재채색(B안)으로 (`Recordings/weapon_color_mockup_2026-10-09.png`, 2026-10-09). 규칙은 [Weapons §2](Systems/Weapons.md#2-무기-슬롯)·[PixelArtUI §7](Systems/PixelArtUI.md#7-스프라이트-팩과-외곽선-규칙).
- **무기 개조** — 성장 시스템 로드맵 ②. 자루당 하나 붙어 런 끝까지 가는 개조 4종 — 폭발(탄환이 반경 0.8의 폭발 탄환이 된다 — 처음엔 적중마다 피해 50%의 추가 폭발이었다가 2026-10-12 런처의 폭발 탄환 규칙으로 합침, 런처는 반경 ×1.5)·유도(앞쪽 좌우 45°·거리 5 안의 가장 가까운 적으로 초당 180°까지 선회, 발사 후 0.1초는 직진)·도탄(튕김 +3)·관통(관통 +2). 데이터는 `ModData`(`Assets/Data/Mods`). 무기 보상 화면에 획득·레벨업과 섞여 나오고, 카드 한 장마다 종류를 1:1:1 가중치로 먼저 뽑는다. 개조 카드는 제목 `MOD`(분홍)·대상 자루의 그림과 `LV5H` 배지·`+HOMING`(분홍)·레벨업 카드처럼 모든 스탯 줄과 바뀌는 줄의 화살표(`PIERCE 1 → 3`, 없던 속성은 `BOUNCE - → 3`, 2026-10-11), 빌드 타일 배지 뒤에 개조 머리글자, 툴팁에 `MOD HOMING`, 개조된 자루의 레벨업 카드는 합친 수치와 수치 없는 개조 이름 줄. 디버그 도구에서 자루를 골라 바로 붙인다 (2026-10-10). 규칙은 [Mods](Systems/Mods.md), 제목 색 목업은 `Recordings/mod_card_color_mockup_2026-10-10.png`. 플레이 테스트는 진행 예정 참조.
- **카드의 얻는 값 초록** — 고르면 얻는 값을 `UPGRADE`와 같은 초록으로: 레벨업·개조 카드의 화살표 뒤 다음 값, 획득 카드의 모든 값(라벨은 흰색), 유물 카드의 수정치 값. 라벨·현재 값·화살표·바뀌지 않는 값과 이미 가진 개조 이름은 흰색 (2026-10-11). 획득 카드를 줄 전체 초록·`NEW`의 노랑·`- → 값`으로 두는 안을 목업해 뺐다. 규칙은 [Weapons §3](Systems/Weapons.md#3-무기-획득과-강화) 카드 표시.
- **동시 사격·탄환 분리 반경 축소** — 글로벌 최소 발사 간격 0.1s → 0. 자루마다 제 쿨다운대로 쏘고 누르는 순간 일제사격으로 시작해, 초당 10발 상한에 묶였던 화력이 자루 수에 비례한다 (Lv.1 시뮬레이션의 초당 피해 6종 144 → 245). 탄환 분리 반경은 0.6 → 0.2(힘 3 유지) — 일제사격으로 몰린 탄이 고른 격자로 펴지던 것을 떨어진 자리 그대로 남게 했다. 둘 다 값만 바꿨고 간격·점사 예외·우선순위 코드는 그대로다 (2026-10-12). 규칙은 [Weapons §1](Systems/Weapons.md#1-핵심-규칙)·[GDD §3.1](GDD.md#31-탄환--공통-원칙).
